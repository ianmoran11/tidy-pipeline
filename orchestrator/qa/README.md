# QA scripts

The scripts used to review agent recipes and pipeline output. Run them from the
project root, e.g. `Rscript orchestrator/qa/inventory.R`. Intermediate results go to
`orchestrator/qa/cache/`, which is gitignored and regenerated by the scripts.

They are review tools, not part of the pipeline: they print summaries for a person
to read. All read `tidy-data-asset-status.sqlite3` read-only.

## After each agent batch

A batch is a list of workbook file names, one per line (`agents/batch-*.txt`). The
batch name is the file name without `.txt`.

```bash
Rscript orchestrator/qa/select_batch.R agents/batch-x.txt 1000 '^aihw-child'   # pick the next batch (optional)
# ... run the agents: agents/run_agents.sh -j 6 $(cat agents/batch-x.txt)
Rscript orchestrator/qa/batch_recipes.R agents/batch-x.txt   # status, failure types, drafts
Rscript orchestrator/qa/compare_reference.R batch-x          # ABS historical: labels per cell vs database
Rscript orchestrator/qa/disagreements.R batch-x criminal-courts-australia 3 4   # worst sheets, with label texts
Rscript orchestrator/qa/ref_gaps.R batch-x                   # missing label texts; database cells not in recipes
Rscript orchestrator/qa/compare_accepted.R agents/batch-x.txt   # accepted 2020+ releases: values and labels (sampled)
```

| Script | Checks | Run time |
|---|---|---|
| `select_batch.R` | Unfinished workbooks, most recent years first, up to a sheet budget, filtered by publication regex | seconds |
| `batch_recipes.R` | Recipe status per sheet; groups `needs_review` failures by type | seconds |
| `compare_reference.R` | For every value cell, the label *cells* the recipe attaches vs. the database's (`source_cell_observation`, historical ABS releases). Outcomes: exact, missing (label kept as sheet meta), missing, extra, different. Also coverage both ways and label collisions | ~0.35 s per sheet |
| `disagreements.R` | The sheets with most disagreements, with the text of the missing/extra label cells | seconds |
| `ref_gaps.R` | Most common missing label texts; database cells not in any recipe, and whether they are blank in the sheet | ~1 min |
| `compare_accepted.R` | Samples 120 cells per sheet from accepted observations (`observation`, 2020+ releases): value match (published value) and whether each `raw_*` label is found in the recipe's labels, title or sheet meta | ~1 s per sheet |
| `compare_text.R [pub regex]` | Text-level label comparison for AIHW, RoGS and EEH, whose reference labels have no cell addresses. Needs `inventory.R` first | ~0.4 s per sheet |

**How to read the results.** These disagreements are benign:
- a header caption ("Method of finalisation", "NUMBER") counted as a label by the
  database;
- labels kept as sheet meta (title, units);
- blank cells the database records as `not_applicable`/`not_available` (ISSUES.md I5);
- unit columns in RoGS that the recipe adds as `unit`.

Look closely at "different labels" and at whole-block patterns. The two real
errors so far, `court_level` from value cells, would show as different labels.
The database has its own errors (ISSUES.md I14), so check the sheet before
blaming the recipe.

## Whole corpus

| Script | Purpose |
|---|---|
| `state.R` | Recipe counts by status, kind and publication; sheets left |
| `inventory.R` | One row per recipe → `cache/recipes.rds` (needed by `compare_text.R`, `corpus_checks.R`, `test_published_value.R`) |
| `corpus_checks.R` | Reference-independent checks over all data recipes: duplicate label sets, hierarchy rows, numeric labels, meta use |
| `check_all_meta.R` | Reruns the validator over every data recipe (used to confirm the meta-on-value-cells check flagged only 2) |
| `test_published_value.R` | Unit tests for `R/published_value.R`, then published vs stored text on 200 sampled sheets |
| `duplicates.R`, `dup_summary.R` | Fingerprint every sheet; find repeated sheets and workbook pairs (basis for the reference-only archive) |

## Normalisation and harmonisation

These read the `targets` store, so run `tar_make()` first.

| Script | Purpose |
|---|---|
| `check_normalised.R` | `normalise()` on a hand-made example, then checks `data_normalised` keeps row/col/address/.value |
| `harmonise_scope.R` | Scope analysis behind the harmonisation proposal: titles with state/period/court level, missing dimensions |
| `harmonise_labels.R` | Distinct (dimension, label) pairs after normalisation → `cache/normalised_pairs.rds`; candidates for `split` |
| `check_harmonised.R` | Values unchanged, gap counts by publication, derived dimensions, before/after examples, no multi-value fields |
| `after_scan.R` | Compound labels still left after harmonisation (ISSUES.md I12) |
| `integration_conflicts.R <publication_id> [n] [numbers\|all]` | Values that still can't be told apart, with the tables involved (ISSUES.md I26) |
| `check_integrated.R` | Reads `integrated/*.csv` as an analyst would: links, duplicates, one `is_latest` per series and period, the README example |
| `blank_cells_vs_reference.R [n]` | Blank-cell records vs the database's blank cells on sampled historical ABS sheets: precision and recall (ISSUES.md I5) |
| `verify_court_cubes.R` | Evidence for the 2009–10/2010–11 Courts cube → court level mapping in the measure spec |

## `seeds/`: one-off generators (history)

These wrote the first version of files that are now hand-edited. **Rerunning them
overwrites those edits.** They are kept to show how each file was derived.

| Script | Wrote |
|---|---|
| `raw_values.R` → `seed_normalisation_spec.R` | `normalisation/normalisation_spec.json` |
| `seed_measure_spec.R` | `measures/measure_spec.json`. Later edits made directly in the JSON: cube court levels, rate standardisation, `replace_labels`, `sentence_basis` flags |
| `seed_harmonisation_spec.R` → `seed_harmonisation_dates.R` | `harmonisation/harmonisation_spec.json` (the second adds `reference_dates`) |
| `names.R` → `build_dictionary.R` | `dictionary/dimensions.csv` |
| `compare_normalized.R` → `build_reference_only.R` | `source-spreadsheets-xlsx/reference-only/reference-only.csv` and the archive file list |
| `backfill_generation.R` | Added `generation` to recipes written before `submit_recipe` recorded it (`--dry-run` available) |

Scripts were tested from this folder on 2026-11-01:
- the batch chain, on a 2-workbook batch with no disagreements and a 3-workbook batch
  with disagreements;
- `compare_text.R` on RoGS;
- `inventory.R`, `test_published_value.R` and `check_harmonised.R`.

Also tested on 2026-11-01, against the integrated targets: `integration_conflicts.R`,
`check_integrated.R`, `blank_cells_vs_reference.R` and `verify_court_cubes.R`.

The seeds were only checked to parse.
