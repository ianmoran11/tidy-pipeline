# Normalisation spec

`normalisation_spec.json` drives `normalise()` (`R/normalise.R`), the first stage after
extraction. It replaces the publisher's dimension names and label spellings with
canonical ones. It never changes a cell, a value or sheet-level metadata. Edit the JSON
directly; `tar_make()` reruns `data_normalised` and everything after it.

For each record and each table's table-level labels, in order:

1. **`dimension_names`:** raw name → canonical name, e.g. `"State/territory": "state"`.
   Names come from `dictionary/dimensions.csv`.
2. **`clean`:** regex replacements (PCRE) applied in order to every label:
   - collapse whitespace and line breaks;
   - trim;
   - drop trailing footnote markers (`(a)`, `(b)(c)`, `(12)`);
   - drop a revision `r` before a number (`r2010–11`).

   Older releases pad and annotate labels heavily (`'  SA   '`, `'NSW(a)  '`). The
   same cleaning is applied to the keys of `values`, so entries written for raw labels
   still match. Leading spaces sometimes show hierarchy in old tables; the raw labels
   remain in the `data` target.
3. **`values`:** canonical dimension → raw label → canonical label, e.g. `"state": {"New
   South Wales": "NSW"}`. Labels not listed are kept, cleaned. `"Total"` is
   deliberately not mapped to a fixed meaning: a population total is resolved by
   `identify()` (`replace_labels`).

`normalise()` makes one pass over `values`. An entry whose target is itself another key
leaves the middle label behind. `check_data_normalised()` fails on such chains
(`labels_are_canonical`).

The first version was generated by `orchestrator/qa/seeds/seed_normalisation_spec.R`.
Since then it has been edited by hand: population and sentence-basis spellings, chain
fixes and `clean`.
